# biesVM - A Compiler for the Functional Language bies

## Glossary

- **bies**: A functional language designed to support operations such as arithmetic, logic, and string and list manipulations.
- **biesVm**: A compiler for the BIES language that generates code for the BiesEnv virtual machine.
- **BiesEnv**: A stack-based virtual machine for executing biesAsm code.
- **biesASM**: Assembly-like instructions generated by the BiesVm compiler.

## Introduction

`BiesVm` is a prototype compiler developed to generate code for the virtual machine `BiesEnv` as part of an academic project for the BIES language. This compiler is the second phase following the `BiesEnv` interpreter, completing a two-part system: a stack-based virtual machine (`BiesEnv`) and a compiler (`BiesVm`) for the BIES language. `BiesVm` is designed to parse BIES code, perform syntactic and semantic analysis, and compile it into assembly-like instructions (`biesASM`) compatible with `BiesEnv`.

## Language Overview

The BIES language is a functional language designed to support operations such as arithmetic, logic, and string and list manipulations. It includes conditional expressions (`if-then-else`), declaration constructs (`let`, `fun`, and `let-in`), and block expressions in sequences (`{ ... }`). Key aspects include:
- **Data Types**: Supports numbers, strings, booleans (`true` and `false`), and lambdas (denoted by `=>` as in JavaScript).
- **Identifiers**: Follow JavaScript naming conventions but cannot begin with `$`. Strings are enclosed in double quotes (`"`), while lists use JavaScript-style array syntax, allowing nesting.
- **Scoping**: Uses nested scopes with constructs such as `let-in` and lambdas, where `let-in` declarations introduce a new, nested scope for the defined variables.

The code in a `.bies` source file is implicitly wrapped within a `main` function, allowing the BIES language to encapsulate code at runtime in the `BiesEnv` environment.

## Prerequisites

To run this project, ensure you have the following:
- **Node.js** (ES6+)
- **ANTLR4** for parsing the BIES grammar
- **Terminal** to execute commands

## Installation

1. Open the package directory:
   ```bash
   cd BiesVm
   ```
2. Install dependencies:
   ```bash
   npm install -g
   ```
3. Build the ANTLR grammar:
   ```bash
   npm run antlr
   ```
4. Read and do the installation process in the `BiesEnv` package.

## Usage

### Compiling a Source File

To compile a BIES source file (`.bies`) into assembly-like instructions (`.biesASM`), use the `biesc` command:

```bash
biesc file.bies [options] 
```

*makes sure to have the file in the `input_files` folder.*

#### Command Options

- `--o outfile`: Specifies the output file for the compiled code. If omitted, the output file will take the source filename without its `.bies` extension. 

*This file will be saved in the`output_files` folder.*

  - Example: 
    ```bash
    biesc source.bies --o compiledFile.biesASM
    ```
- `--e errfile`: Specifies a file for logging errors encountered during compilation. If omitted, errors are logged to the console.

*This file will be saved in the `errors` folder.*

  - Example: 
    ```bash
    biesc source.bies --e errors.log
    ```

#### Example Usage

- Basic compilation:
  ```bash
  biesc source.bies
  ```
- Compilation with specific output file:
  ```bash
  biesc source.bies --o compiledFile.biesASM 
  ```
- Compilation with error logging:
  ```bash
  biesc source.bies --e errors.log
  ```
- Combining both options:
  ```bash
  biesc source.bies --o compiledFile.biesASM --e errors.log
  ```

### Compiling and Running a Source File

With the `biesRun` command, you can compile a `.bies` source file and run the compiled code in one step:

```bash
biesRun file.bies [options]
```

#### Command Options

- `--o outfile`: Specifies the output file for the compiled code. If omitted, the output file will take the source filename without its `.bies` extension. 

*This file will be saved in the`output_files` folder.*

- `--e errfile`: Specifies a file for logging errors encountered during compilation. If omitted, errors are logged to the console.

*This file will be saved in the `errors` folder.*

#### Example Usage

- Compile and run a source file:
  ```bash
  biesRun source.bies
  ```
- Specify a custom output file for the compiled code:
  ```bash
  biesRun source.bies --o compiledFile.biesASM
  ```
- Log errors to a specific file:
  ```bash
  biesRun source.bies --e errors.log
  ```
- Combine both options:
  ```bash
  biesRun source.bies --o compiledFile.biesASM --e errors.log
  ```

### How It Works

1. **Compiles the Source File:**
   - `biesRun` invokes the `BiesVM` package to compile the `.bies` file into a `.biesASM` file.
2. **Executes the Compiled Code:**
   - Automatically switches to the `BiesEnv` package to execute the compiled `.biesASM` file.
3. **Displays the Output:**
    - The output of the executed code is displayed in the console.

### Testing the Compiler with Multiple Files

You can test the compiler against multiple `.bies` files in the `./input_files` folder using the script in `testCompiler.js`. This script compiles each file and logs errors or outputs for each one.

#### Running the Test

```bash
npm run test
```

#### What It Does

1. Scans the `./input_files` directory for `.bies` files.
2. Compiles each file using the `BiesVM` compiler.
3. Saves the compiled output in `./output_files`.
4. Logs errors (if any) in `./error_logs`.

#### Example Output

If you have two files (`test1.bies` and `test2.bies`) in `./input_files`, you might see:

```bash
Encontrados 2 archivos para probar.

Compilando: test1.bies
✅ test1.bies se ha intentado compilar exitosamente. En caso de errores, revisa el archivo de errores.

Compilando: test2.bies
❌ Error al compilar test2.bies.

Pruebas completadas.
```
